## Decision-rule outcome: third arm

Verified success is 50% (full) and 65% (serial). The plan's rule says:
the live-model prompt contract is the problem, not the harness. Fix
shaping, re-run, **do not publish comparisons** until both modes verify
reliably. This report therefore makes no full-vs-serial claim. (For the
record, wall clocks are identical — evidence reads are local and the
~15 s model call dominates both modes.)

## Findings

1. **Output reserve 1024 → 4096 (product fix, user-approved).**
   At 1024 the model died with `finish: length` mid-patch; the same
   prompt completes as valid JSON at 4096 (~850–1250 completion tokens
   including ~140–230 reasoning tokens). Changed
   `OUTPUT_BUDGET_TOKENS` in `driver.rs` with the evidence cited.
2. **Remaining malformations are model non-compliance, not budget.**
   At 4096 the failures are empty replies and unescaped newlines inside
   `new_content` despite `temperature: 0` + `response_format: json_object`.
   Shaping levers left: repair-tolerant parsing (raw-newline repair),
   retry-on-malformed in the driver, or a different pinned model.
3. **Bench now runs live** (`TACHYON_BENCH_LIVE=1`, `TACHYON_LIVE_*` env);
   scripted path unchanged and default. Live `model_calls` reports None,
   never an invented zero. `temperature: 0` pinned in the shared
   OpenAI-compat adapter for determinism.
